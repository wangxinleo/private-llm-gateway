# Maskit(xiaYuTian11/maskit)设计借鉴分析

> 仓库:https://github.com/xiaYuTian11/maskit(AGPL-3.0)。**只借鉴设计思路,严禁复制代码(AGPL 传染)**。
> 与本项目几乎同构:本地脱敏网关 + `{{LABEL_suffix}}` 语义占位符 + SSE 流式还原 + 桌面壳。其透明代理引擎核心在 `mitm_addon.py`(3905 行),规则在 `shield_defaults.py`。

## 一、生产实证教训(直接修正我们的设计)

### 1. 确定性后缀 = 猜测验证 Oracle(推翻我们的哈希后缀方案)
- `_placeholder`:"Use random per-session placeholders; **never derive IDs from secrets**";`_rand_suffix`:"可预测的后缀会让上游能够枚举、关联同一实体"。
- 我们 R8 原案"原文哈希截 4 位 hex"给上游送了猜测-验证预言机(16^4 空间可离线爆破确认候选值)。**结论:后缀必须密码学随机**。

### 2. 十六进制后缀诱导模型算术变造(0.41% 生产事故率)
- 8798 条 RESTORE 中 36 条未还原,其中 92/97 是:模型看到 `{{IPPRIVATE_83fc6a}}`(192.168.119.5)自行造出 `{{IPPRIVATE_83fc00}}` 表示子网、`{{IPPRIVATE_83fc02}}` 表示网关——hex 后缀"长得像能拆开算的数"。
- 修正:**纯辅音后缀**(bcdfghjkmnpqrstvwxz,19 字符;19^6≈4700 万)。无数值可读性;不含元音→与英文单词不相交(宽松修复零误伤);剔除 l/i/o 防与 1/0 形近。后缀长度取 5(19^5≈248 万,请求作用域足够)。

### 3. 模型会剥落花括号 → 宽松修复兜底(degraded 计数)
- `{{...}}` 是 Jinja/Handlebars/Vue 模板语法,模型写 shell/代码时顺手"整理"掉:实测 `X-Setup-Token: SECRET_b5a53c`(无括号)。
- 修法:严格文法优先;宽松 RX `\{{0,2}(LABEL_SUFFIX)\}{0,2}` **仅查映射表命中才替换**(零误伤,绝不猜未签发 token),修复量单独计数 `degraded`——它是"模型在改写输出"的前兆指标。

### 4. 流式还原必须通道化(暴露我们原文层方案的盲区)
- `pending: {通道 → 半截占位符}`,"每个 delta 字段一个通道,避免上一个字段没闭合的占位符拼进下一个字段"。
- **我们原文层还原的缺陷**:占位符被切成两个 delta 事件时,原文层两半之间隔着 `"}}]}\n\ndata:"`,文法断裂→两半各自原样吐出→最常见的切分场景反而还原不了。原文层只对单事件内完整出现的占位符有效。
- 修正:还原下沉到 SSE 事件层——帧拆分(`\n\n`)→ JSON 解析 → 深遍历字符串叶子按 JSON 路径分通道 → 每通道独立 pending → 重组帧;解析失败/未知形状原样透传。流尾残留用 flush_tmpl(克隆最后帧模板补发一个 delta)。

### 5. 脱敏侧防污染
- **防套娃**(`_recall_token`):原文自身命中占位符文法时严禁二次包裹——反查映射还原真值,查不到原样返回。
- **分段保护**(`_mask_excluding_placeholders`):多规则叠加替换前按占位符正则切段,只替换非占位符片段(自定义词表字符可能劈开占位符→永久还原失败)。

### 6. safe-label 规范
- 大写、剔除非 [A-Z0-9]、截 12 字符、空则回退 `TERM`(中文自定义词统一归 TERM)。与我们短码白名单互补。

## 二、评估后不采纳(记录理由)

- **跨请求复用表(24h TTL/2000 条/LRU 续命)+ SQLite 启动预热**:解决"多轮同实体换符"+"历史残留占位符永不自愈"。我们架构下客户端每轮回传还原后明文、逐轮重脱敏,前者不存在;后者仅还原失败边缘场景出现,R5 透传已覆盖。且代价(原文内存驻留 24h + 同原文 TTL 内可关联)违反 D3。**列为未来选项**。
- **响应侧泄漏扫描**(还原后检查回复中不在映射内的 PII,只记录不阻断):好特性,进 backlog。
- **指令注入**:其未做任何注入,纯靠"语义标签 + 随机辅音后缀 + 宽松修复"工程补偿——部分印证 D4 最初删除直觉;我们保留 D4 v3 受控注入(auto|off),双保险。
