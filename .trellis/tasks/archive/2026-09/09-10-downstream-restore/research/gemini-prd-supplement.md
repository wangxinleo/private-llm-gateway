# 需求补充说明:下行无感还原(gemini-3.8-flash 产出)

> 来源:OpenChamber session `ses_f75b3c1feffeg39jND1wip2OBk`,2026-09-10。已合并收敛进 prd.md,本文存档原文。

## 1. 用户故事

- **US-01(单轮多敏感值)**:单次对话发送多个敏感数据(不同手机号、多个 API Key),模型回复提及时准确显示真实明文且互不混淆,无需手动比对替换。
- **US-02(SSE 流式打字机)**:流式交互下网关实时还原占位符,即使占位符跨 chunk 切分(甚至单字节切分),打字机输出平滑连贯,感知不到还原引起的卡顿或格式破损。
- **US-03(多轮对话历史回显)**:多轮历史作为上下文发送时,本轮回复中引用的占位符仍能按当前请求映射表正确还原,保证上下文逻辑一致。
- **US-04(非流式 JSON)**:`stream: false` 时返回的标准兼容 JSON(含 `message.content`、`tool_calls` 等字段)已全量透明还原,下游业务直接解析消费。

## 2. 验收标准

- **AC-01 多敏感值精确映射**:Given 请求含手机号 A、B 与密钥 X,分配 `<<PRIVACY_MASK:PHONE:1>>`、`<<PRIVACY_MASK:PHONE:2>>`、`<<PRIVACY_MASK:SECRET:1>>`;When 回复同时引用三者;Then 分别精确还原,无串位错位。
- **AC-02 SSE 跨 Chunk 切分平滑还原**:Given 占位符分布在连续多个 chunk(前缀/内部/尾部切分);When 流式解码器收到分片;Then 滑动缓冲识别完整占位符并替换明文下发;非占位符文本保持最低延迟冲刷。
- **AC-03 未命中与未知占位符原样透传**:Given 幻觉占位符(如 EMAIL:99)或旧格式无映射;When 经过还原层;Then 原样透传,不抛异常、不阻断流。
- **AC-04 审计与还原边界隔离**:Given 敏感请求获得还原明文响应;When 记录审计;Then 审计仅含占位符;还原严格发生在审计之后的响应出口边界。
- **AC-05 流异常中断不吞已还原数据**:Given 上游超时/重置/客户端 Abort;When SSE 非正常终止;Then 已还原输出不回滚,缓冲区已解析有效文本正常 flush,安全关闭。

## 3. 边界与异常场景

**切分与缓冲**:单字节分片;假前缀(`<<PRIVACY_POLICY>>`)判定失败立即顺序释放不丢字;流尾悬挂前缀(`<<PRIVACY_MASK:`)EOF 前 flush;分片跨越 `data: ` 协议前缀(还原器工作在 payload 文本层)。
**结构变体**:无缝拼接多占位符;Markdown 行内/多行代码块内仍还原;嵌套畸形占位符单遍处理不递归;同值多现稳定还原同一明文。
**复杂载荷**:占位符在 `tool_calls[].function.arguments` JSON 字符串内,还原不破坏 JSON;上游 4xx/5xx 错误体回显占位符按同规则还原。
**生命周期**:并发请求各自独立 Request Scope 映射表严禁串车;请求完成/断开/超时后映射表确定性回收。

## 4. 非目标

跨请求持久化映射;客户端侵入式 SDK;模糊容错匹配(拼写变异不纠错);审计明文反查;端到端传输加密扩展。
