# 本地 NER 语义实体识别评估（Node/Next standalone 网关）

> 结论：**no-go（本批次不做）**，记为"待触发再评估"。触发条件与前置调研项见 §7；若触发，按 §6 草图实施。
> 事实标注：[实测] = 本项目或竞品源码直接核实；[估计] = 量级推断未实测；[待验证] = 需原型确认。

## 1. 背景与差距

- 我方请求侧 PII 覆盖 = 12 条结构化规则 + 自定义词库（`src/scanner/pii.ts`、`src/scanner/custom-words.ts`）[实测]。
- 差距：自由文本中的**人名、机构名、地址**无自动检测；只能靠用户手工往词库加词（词库的存在证明需求真实，但维护成本高、覆盖滞后）。
- 竞品证据（maskit v0.3.0，2026-09-19）[实测：CHANGELOG + ner_engine.py + 相关提交]：
  - 本地 ONNX 中文 BERT NER，`ner_enabled` 默认关；
  - 样例集明文残留 **74% → 11%**（"规则 + NER"，其自测口径）；
  - 为分发模型给 CI 增加模型拉取与打包步骤（All-in-One 包）——**打包/分发成本有独立证据**；
  - 接入踩坑：① NER 在**已脱敏文本**上抽取 → 实体残片明文上行，改为干净原文抽取 + OffsetMap 映射回"伤疤坐标系"；② 优先级契约（自定义词/内置规则 > NER）；③ 非汉字跳过（否则英文参数被当实体误脱 → 上游 400）；④ 协议控制键保护。

## 2. 我方架构约束（决定选项可行性的关键）

| 约束 | 事实 |
|---|---|
| 运行形态 | Next.js standalone 单容器（`Dockerfile` 两段 node:22-alpine），产物 `server.js` + 复制原生模块（现已有 better-sqlite3 先例） |
| 扫描架构 | **单遍**：窗口扫描 → 自定义词 → `applyMasks` 一次替换（`json-mask.ts` 逐叶扫描、字节级 splice） |
| 性能基线 | 1MB/200 findings ≈ 427ms；病态 1.2MB/11k findings ≈ 1001ms（已有基准守护） |
| 部署面 | 用户自托管；镜像体积与冷启动是真实成本（模型会进镜像） |
| 隐私原则 | 全本地推理、零外发；不做云 PII 服务 |

**关键判断（架构层面）**：maskit 的"坐标漂移"根因是其引擎**多阶段顺序替换**（规则先替换文本、NER 再跑在被改过的文本上）。我方是单遍架构——若 NER 作为**同一遍的另一个 detection 源**（在原始文本上产出 spans/findings，与规则 findings 一起交给 `applyMasks`），则**不存在**坐标漂移类 bug；只需保证 NER span 与规则 findings 的去重/最长优先（`applyMasks` 已实现）与占位符不劈开（已有分段保护）。这是引入 NER 的**重大架构红利**，也意味着 maskit 的 OffsetMap 机制对我方**不必要**（其教训的核心——"永远在干净原文上抽取"——我方天然满足）。

## 3. 选项对比

| 选项 | 形态 | 优点 | 缺点/成本 | 结论 |
|---|---|---|---|---|
| A. onnxruntime-node（进程内 ONNX） | 新增原生依赖 + 模型文件 | 性能最好；与 better-sqlite3 同为原生依赖，Dockerfile 复制模式已有先例 | 原生二进制体积（多平台）；模型进镜像；Node ABI 与镜像版本耦合；需量化模型 [待验证] 具体版 | 最可行的 go 路线 |
| B. transformers.js（WASM） | 纯 JS/WASM | 无原生依赖，打包简单 | CPU 推理慢（估计 3-10x）；WASM 内存与长文本分块更费 [估计]；仍需模型文件 | 备选（低吞吐场景） |
| C. 独立 sidecar（Python NER 服务） | compose 加服务 | 模型生态最好 | 违反"单容器/简单部署"定位；运维面翻倍；跨进程延迟与故障域 | 不做 |
| D. 暂不做（维持词库路线） | — | 零成本、零风险；把工程投入放在已验证的缺口（T1/T2 级缺陷）上 | 语义实体覆盖仍缺失 | **本批次采纳** |

## 4. 成本/收益量化（若走 A）

| 维度 | 量级 | 说明 |
|---|---|---|
| 模型体积 | BERT-base 级中文 NER，fp32 ~400MB、int8 量化 ~100MB [估计，待验证] | 镜像增量即模型大小；需选小模型或蒸馏版 |
| 内存 | 常驻数百 MB 级 [估计] | 与 better-sqlite3/Next 共存；小机器（1-2GB）吃紧 |
| 延迟 | 单次 512 token 切片 CPU 推理 ~20-100ms [估计]；1MB 级提示需分块，累计可达数百 ms | 与现有 P50 基线（~600ms 端到端）同量级，需分块+预算控制 |
| 打包/CI | 模型下载 + 校验 + 进镜像/发布包 | maskit 为此专门改 CI [实测]；我方需在 Dockerfile/构建流程加同样步骤 |
| 实现 | 新 scanner 阶段 + 开关 + 测试 + 性能门槛 | 参照自定义词阶段的接入面 |

收益：把"人名/机构/地址"从完全漏检变为大概率覆盖（maskit 自测 74%→11%，其口径不可直接外推到我方语料 [待验证]）；与词库互补。

## 5. 风险

1. **误报**（对隐私网关是首要风险）：中英混排、代码标识符、版本串、模型/产品名被识别为人名/机构；需专有 FP 语料（我方仓库文本 + 典型 prompt 语料）做门槛。
2. **上游 400**：误脱英文参数/协议字段（maskit 同款坑）→ 必须复用其纪律：非目标语言跳过 + 协议控制键保护（我方不改键名、跳过面在 `json-mask` 已收口）。
3. **性能回归**：长文本分块推理拖慢 P50/P95；必须有开关（默认关）与预算上限（超过 N 字节走抽样/截断策略）。
4. **隐私边界**：模型本地、输入不出机；但模型文件引入供应链问题（来源与校验和需固定）。
5. **维护**：模型升级、ABI、跨平台构建（linux/arm64 等）。

## 6. 实施草图（仅当触发再执行）

1. 模型选型：中文 NER（BERT 级，int8 量化 ONNX），固定版本 + 校验和；体积目标 ≤150MB [待验证]。
2. 运行时：`onnxruntime-node`；Dockerfile 参照 better-sqlite3 的复制模式补原生模块；探针环境先验证 ABI。
3. 接入：新 scanner 阶段 `scanNer(text) -> Finding[]`（category: `NER_PERSON`/`NER_ORG`/`NER_LOC`，短码规范沿用 `mask-tag`），**在原始文本上产出 span**，与规则 findings 合并后走同一次 `applyMasks`（避免多阶段坐标问题）；默认关的规则开关 + `NER_MAX_BYTES` 预算。
4. 纪律（逐条映射 maskit）：
   - 优先级契约：结构化规则/自定义词 > NER（去重与最长优先已由 `applyMasks` 保证，需加显式用例锁定）；
   - 非目标语言/非汉字段跳过（防英文参数误脱）；
   - 分块边界不产生跨块半实体（重叠窗口 + span 去重）。
5. 测试：正负语料（人名/机构/地址正例；代码/版本串/英文参数反例）；长文本分块一致性（同一文本不同分块路径 finding 一致）；性能门槛（1MB 文本 ≤ 预算）。
6. 发布形态：模型不进默认镜像时提供"模型包"下载与校验步骤（参照 maskit 的分发教训）。

## 7. Go 触发条件与前置调研项（本批次 no-go 的理由）

触发条件（任一满足再评估）：
- 用户明确反馈"人名/地址漏检"是主要痛点（有真实 case 而非假设）；
- 词库路线出现规模瓶颈（词条数/维护成本失控）；
- 出现 ≤50MB 且质量可接受的中文 NER 量化模型 + Node 侧打包方案被验证。

前置调研项（先做小、可逆的原型）：
- [ ] 选 2-3 个候选模型，分别测：体积、内存、512/2k token 延迟、我方语料 FP 率（用仓库文本 + 10 条典型 prompt 构造负例集）；
- [ ] Dockerfile 原生模块复制可行性（onnxruntime-node ABI × node:22-alpine × arm64/amd64）；
- [ ] 预算策略（超长文本抽样/截断）与开关默认值评审。

## 8. 结论

本批次 **no-go**：语义实体覆盖是真实缺口，但（a）工程与部署成本高且有独立证据（maskit 的 CI/打包改造），（b）收益数字来自竞品自测、在我方语料上未验证，（c）当前批次已修复两个实证缺陷（T1/T2）且补了 IPv6 覆盖。先以 §7 原型验证低层不确定性，再决定是否立项实现。若触发，按 §6 实施。
