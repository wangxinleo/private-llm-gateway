# 审计日志与最近拦截记录「删除对不上」— 查询口径不一致

## Goal

消除「总揽页最近拦截记录有数据、审计日志页却显示为空」的口径不一致：审计页时间筛选新增「全部」并设为默认，使两页对同一份 `audit_log` 数据的呈现可互相对照，用户不再误以为数据被删除。

## Background（评审结论，浏览器 + API 双重复现，2026-09-11）

数据完全同源且**没有被删除**，差异纯在查询口径：

- 两页均读 SQLite `audit_log` 单表（`src/audit/store.ts:12`）。运行实例（PID 33784）使用的库为 `data/test-audit.sqlite`，共 193 条（158 allow + 34 mask + 1 block），最新记录 **2026-08-06**；顶层统计卡（193/1/34/158）与库内一致，证明无删除发生。
- **总揽页**「最近拦截记录」`src/components/dashboard-content.tsx:57-64`：`/api/admin/audit?limit=10&action=block|mask`，不带时间筛选，取全局最新 10 条。
- **审计页** `src/components/audit-table.tsx:256` 默认时间范围 `"today"`，`buildUrl`（`:294-309`）永远强制携带 from/to；时间选项（`:285-292`）只有 本日/近3天/本周/本月/近3月/近6月，无「全部」。
- 实测（今日 2026-09-11）：审计页默认视图 0 条（「未找到审计记录」）；总揽页显示 8/6 的 1 block + 10 mask；审计页切「近3月」后同批记录全部出现（截图确认）。

## Requirements

- R1 审计页时间范围新增「全部」（`all`）选项，并设为**默认**；选中时不向 `GET /api/admin/audit` 传 `from`/`to`。
- R2 其余时间选项行为不变（照常携带 from/to）；「清除筛选」按钮重置目标改为「全部」；`hasFilters` 判断同步适配（`audit-table.tsx:537,594`）。
- R3 空态兼容提示：筛选后结果为 0 且库内存在记录时，空态区提示「当前筛选无匹配，库内共有 N 条记录」并提供「查看全部」一键重置（N 通过一次无筛选请求取 total）。
- R4 总揽页「最近拦截记录」口径保持不动。
- R5 纯前端改动，后端 API 与表结构不变。
- R6 审计页布局改为「列表内部滚动」：条目过多时仅表格区域滚动，筛选栏、工具栏、分页常驻可见（shell 全页滚动不再把工具栏顶走）；表头在滚动区内 sticky。

## Acceptance Criteria
